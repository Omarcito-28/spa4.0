# Documentación del proyecto

Carpeta para guardar los entregables de **Essence De Toi**, el sistema web de control operativo y agendamiento para Centros de Cuidado Personal. Cuando agregues un documento, enlázalo en la tabla y actualiza su estado.

| # | Entregable | Archivo sugerido | Estado |
|---|------------|------------------|--------|
| 1 | Propuesta del proyecto | `propuesta.md` / `propuesta.pdf` | Pendiente |
| 2 | Requerimientos funcionales y no funcionales | `requerimientos.md` | Pendiente |
| 3 | Historias de usuario | `historias-de-usuario.md` | Pendiente |
| 4 | Pila del producto (Product Backlog) | `pila-del-producto.md` | Pendiente |
| 5 | Documento de arquitectura de software (SAD) | `sad.md` | Pendiente |
| 6 | Diagramas UML (casos de uso, clases, secuencia, despliegue) | `uml/` | Pendiente |
| 7 | Lógica de datos (modelo de datos y colecciones de MongoDB) | `logica-de-datos.md` | Pendiente |
| 8 | Plan y evidencias de pruebas | `pruebas.md` | Pendiente — las pruebas automatizadas ya están en el código (ver [README](../README.md#pruebas)) |
| 9 | Despliegue | [`despliegue.md`](despliegue.md) | Listo |
| 10 | Apartado de uso de IA | `uso-de-ia.md` | Pendiente |

## Convenciones

- Escribe los documentos en Markdown cuando sea posible, para que se puedan revisar en los pull requests. Si un entregable debe ser PDF, guarda también su fuente editable.
- Las imágenes y diagramas exportados van en una subcarpeta con el nombre del entregable (por ejemplo `uml/clases.png`).
- No guardes aquí contraseñas, URIs de bases de datos ni otros secretos.
